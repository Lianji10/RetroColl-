4.7. Descripción detallada de funcionalidades

• Módulo de Autenticación y Perfil: Sistema basado en tokens JWT para la gestión de sesiones. Incluye una interfaz de acceso y registro, además de un panel de usuario para la edición de datos personales, gestión de credenciales y visualización de productos en venta.

• Gestión de Productos y Catálogo: Interfaz de exploración con filtros dinámicos por categorías y consolas. La ficha de producto muestra imágenes alojadas en el servidor, descripción técnica, estado de conservación y datos de contacto del vendedor.

• Formulario de Publicación: Herramienta para vendedores que permite la subida de imágenes y la categorización precisa del producto mediante selectores dinámicos alimentados desde la API. Incluye funciones de edición y borrado lógico de publicaciones.

• Sistema de Transacciones y Carrito: Implementación de un carrito persistente en el navegador que permite gestionar múltiples artículos. El proceso de checkout integra un formulario de envío y selección de pasarela de pago (simulada) para finalizar el pedido.

• Reglas de Integridad y Valoración: Lógica de negocio que impide la compra de productos propios y gestiona el cambio automático de estado de "Disponible" a "Vendido". Incluye un sistema de feedback entre usuarios para garantizar la transparencia del marketplace.

5.3. Diseño Físico (Migraciones de Laravel)

En RetroColl, el diseño físico de la base de datos se gestiona mediante las Migraciones de Laravel. Este enfoque permite definir la estructura de las tablas de forma programática y versionada, facilitando el mantenimiento y la consistencia entre entornos de desarrollo.

• Tabla USUARIO (Cuentas y Perfiles):
Gestiona la autenticación y los datos de contacto. Se han incluido campos para el control de roles (usuario/admin) y un sistema de valoración promedio que se actualiza dinámicamente.
```php
Schema::create('USUARIO', function (Blueprint $table) {
    $table->id('id_usuario');
    $table->string('nombre', 100);
    $table->string('email', 100)->unique();
    $table->enum('rol', ['usuario', 'admin'])->default('usuario');
    $table->string('password', 255);
    $table->date('fecha_registro')->default(now());
    $table->decimal('valoracion_promedio', 3, 2)->default(0);
    $table->timestamps();
});
```

• Tablas Maestras (CATEGORIA y PLATAFORMA):
Estructuras simples encargadas de la organización del catálogo. Permiten una clasificación normalizada de los videojuegos y consolas.
```php
Schema::create('CATEGORIA', function (Blueprint $table) {
    $table->id('id_categoria');
    $table->string('nombre', 50);
});
// Estructura idéntica para PLATAFORMA
```

• Tabla PRODUCTO (Inventario):
Es el núcleo del sistema. Almacena la información de los artículos, su estado y la ruta de la imagen en el servidor. Utiliza claves foráneas para vincularse con el vendedor y su clasificación.
```php
Schema::create('PRODUCTO', function (Blueprint $table) {
    $table->id('id_producto');
    $table->string('titulo', 150);
    $table->text('descripcion')->nullable();
    $table->decimal('precio', 10, 2);
    $table->string('estado', 50)->nullable();
    $table->string('imagen', 255)->nullable();
    $table->unsignedBigInteger('id_vendedor');
    $table->unsignedBigInteger('id_categoria');
    $table->unsignedBigInteger('id_plataforma');
    $table->foreign('id_vendedor')->references('id_usuario')->on('USUARIO')->onDelete('cascade');
    $table->timestamps();
});
```

• Tabla COMPRA (Transacciones):
Registra el éxito de una venta. Utiliza una restricción 'unique' en el `id_producto` para asegurar que un producto físico único no pueda ser vendido dos veces.
```php
Schema::create('COMPRA', function (Blueprint $table) {
    $table->id('id_compra');
    $table->decimal('precio_final', 10, 2);
    $table->unsignedBigInteger('id_comprador');
    $table->unsignedBigInteger('id_producto')->unique();
    $table->foreign('id_comprador')->references('id_usuario')->on('USUARIO');
    $table->timestamp('fecha_compra')->useCurrent();
});
```

• Tabla VALORACION (Feedback):
Permite el intercambio de reseñas entre usuarios tras las transacciones, almacenando la puntuación numérica y el comentario textual.
```php
Schema::create('VALORACION', function (Blueprint $table) {
    $table->id('id_valoracion');
    $table->integer('puntuacion');
    $table->text('comentario')->nullable();
    $table->unsignedBigInteger('id_emisor');
    $table->unsignedBigInteger('id_receptor');
    $table->timestamps();
});
```

7. Codificación

En esta sección se detallan las tecnologías utilizadas tanto para el desarrollo del backend como del frontend, justificando las elecciones técnicas en base a las necesidades del proyecto.

7.1. Tecnologías usadas

7.1.1. Backend: Laravel (PHP)
Se eligió Laravel frente a otras opciones (como Node.js o Spring Boot) por las siguientes razones:
- Ecosistema y Productividad: Laravel ofrece herramientas integradas como la consola Artisan y el ORM Eloquent, que aceleran drásticamente la interacción con la base de datos y la creación de la estructura (controladores, modelos, migraciones).
- Seguridad Integrada: Incluye protección nativa contra vulnerabilidades comunes (inyecciones SQL, XSS). Para la autenticación de la API, facilita enormemente la gestión segura de accesos mediante tokens (Sanctum/JWT).
- Curva de aprendizaje y Documentación: Al basarse en PHP, cuenta con una de las mejores documentaciones del mercado, permitiendo implementar lógicas de negocio complejas (como las reglas de compraventa) de forma robusta y ágil.

7.1.2. Frontend: Vue.js 3 (Composition API)
Para la interfaz de usuario se seleccionó Vue.js (específicamente su versión 3 con Composition API) en lugar de alternativas como React o Angular:
- Reactividad y SPA: Permite crear una Single Page Application (SPA), actualizando la interfaz y el DOM de forma reactiva sin recargar la página, lo que brinda una experiencia de usuario fluida y moderna.
- Ecosistema Vue: El proyecto se apoya en `Vue Router` para la gestión de rutas en el lado del cliente y en `Pinia` (el estándar actual de Vue) para la gestión centralizada del estado (como el `cartStore` para el carrito y el `authStore` para la sesión del usuario).
- Ligereza y Curva de Aprendizaje: Es más sencillo de configurar y estructurar para un proyecto de esta escala que Angular, manteniendo un código más limpio y modular que React gracias a sus Single-File Components (.vue).

7.1.3. Estilos: Tailwind CSS
En lugar de usar CSS puro, preprocesadores o librerías de componentes (como Bootstrap), se optó por Tailwind CSS:
- Personalización extrema: Al ser un framework "utility-first", permite crear un diseño único y un sistema de diseño propio (ej. clases personalizadas como `bg-retro-gris` o `text-retro-amarillo`) sin escribir CSS personalizado.
- Rendimiento (PurgeCSS): El proceso de compilación elimina automáticamente todas las clases CSS que no se están utilizando en el código Vue, generando un archivo final extremadamente ligero de apenas unos kilobytes.

7.1.4. Base de Datos: MySQL
Es la elección idónea para este tipo de aplicaciones transaccionales:
- Relacionalidad: La naturaleza del marketplace (Usuarios que tienen Productos, que generan Compras y Valoraciones) requiere una base de datos relacional para garantizar la integridad referencial.
- Integración: Se integra a la perfección con Laravel. La estructura se gestiona íntegramente mediante migraciones, lo que facilita el control de versiones y el despliegue del esquema de base de datos en diferentes entornos.

7.2. Entorno Servidor

El servidor está arquitecturado como una API RESTful que actúa como puente exclusivo de datos. El backend se encarga puramente de la lógica de negocio, validaciones y acceso a datos, devolviendo respuestas estructuradas en formato JSON, desligándose totalmente de la renderización de la interfaz.

7.2.1. Seguridad: Evitar inyección en bases de datos y manipulación
Para garantizar la integridad en RetroColl, se han implementado varias barreras:
- Eloquent ORM y PDO: Todas las consultas a la base de datos se realizan a través de Eloquent, que utiliza por debajo PDO de PHP con vinculación de parámetros (parameter binding). Esto asegura que los datos del usuario se traten como valores literales, haciendo imposible la inyección SQL.
- Validación de Entradas estricta: Antes de procesar cualquier petición (como realizar una compra o publicar un producto), Laravel valida los campos requeridos, sus tipos y formatos (`$request->validate(...)`).
- Lógica de Autorización: Se comprueba en el servidor la propiedad de los recursos. Por ejemplo, la API bloquea activamente (Error 400) los intentos de un usuario de comprar un producto que él mismo ha publicado, aunque el frontend haya sido manipulado.

7.2.2. Evitar o capturar errores y warnings
La estabilidad se mantiene mediante el control proactivo de excepciones:
- Transacciones de Base de Datos: En operaciones críticas como el "Checkout", se utilizan `DB::beginTransaction()` y `DB::rollBack()`. Si falla el registro de la compra o la actualización del estado del producto, la transacción se deshace por completo, evitando inconsistencias (bases de datos a medias).
- Respuestas Controladas (JSON): El servidor captura cualquier error y devuelve una respuesta JSON estandarizada con su código HTTP correspondiente (404 para no encontrado, 422 para errores de validación de formulario, 400 para reglas de negocio incumplidas), ocultando los "stack traces" o "warnings" de PHP al usuario final por seguridad.
- Logs del Servidor: Laravel registra cualquier excepción no controlada en `storage/logs`, permitiendo al desarrollador auditar y solucionar problemas técnicos.

7.3. Entorno Cliente

El cliente es una aplicación SPA completamente desacoplada que se comunica con la API mediante la librería `Axios`. Las peticiones se realizan de forma asíncrona y se gestionan interceptores para inyectar automáticamente el token de seguridad (Bearer Token) en cada solicitud y capturar errores globales (como sesiones expiradas - 401).

7.3.1. Asegurar la funcionalidad en los navegadores más usados
La accesibilidad y compatibilidad del proyecto en navegadores como Chrome, Firefox, Safari o Edge se garantiza mediante la cadena de herramientas de construcción:
- Vite.js: Como entorno de desarrollo y "bundler", Vite compila y transpila el código JavaScript moderno (ES6+) y los componentes Vue a una versión optimizada y compatible con los estándares web actuales, asegurando que cualquier navegador moderno pueda ejecutar la lógica sin problemas.
- Autoprefixer de Tailwind: Durante la compilación de estilos, Tailwind utiliza PostCSS para añadir automáticamente los prefijos de los proveedores (`-webkit-`, `-moz-`) a las reglas CSS que lo requieran, asegurando que los estilos y animaciones se rendericen idénticamente sin importar el motor del navegador.
